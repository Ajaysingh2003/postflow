# draftva backend: Phase 0 audit

Audited 2 October 2026. Scope: current backend against the supplied rewrite spec. No repository files or existing databases were changed. The local SQLite schema was inspected read-only; production services and developer-account approvals were not inspected. The root instructions are in `agents.md` (lowercase); no root/backend `CLAUDE.md` exists. Frontend instructions apply to the frontend, which was left unchanged.

## Assessment

The rewrite structure is largely present, but the backend is not ready for production. The remaining work includes confirmed runtime failures and workspace-isolation failures, not just missing features. The implementation-status document overstates completion.

Confirmed stack: FastAPI; synchronous SQLAlchemy 2 ORM/session; Alembic; Pydantic Settings reading environment variables and `.env`; PostgreSQL in Compose, SQLite locally; custom polling worker/scheduler, with no durable broker-backed job runner. Redis is available but not wired into the outbound publishing limiter. OAuth tokens and Mastodon client secrets use Fernet encryption derived from APP_SECRET. Passwords use Argon2 and session tokens use SHA-256 hashing.

## First fixes required

1. **Real-adapter validation crashes on six platforms.** `publishing/service.py:82` always calls `adapter.validate(..., subreddit_profile=...)`. Only Reddit accepts that keyword. Direct reproduction raises TypeError for X, LinkedIn, Bluesky, Mastodon, Facebook and Instagram. Scheduling and publishing through the common service consequently fail. The pipeline tests use a mock with `**opts`, masking the mismatch.
2. **Workspace isolation is incomplete.** `content/router.py:49` trusts the submitted connected-account ID without verifying its workspace or platform. An isolated API check created a workspace-A post referencing workspace B's Reddit account, returning HTTP 201. Publishing resolves accounts by ID alone. `assistant/service.py:135` also loads voice profiles by ID alone; an isolated check confirmed workspace B's private tone description entered workspace A's prompt. Add checks at both request and job boundaries.
3. **Duplicate-post protection is incomplete.** Both scheduler and worker publish due variants: `process_queue()` aliases `dispatch_due()`. The job reads without an atomic claim/lock and only skips an already completed publication. The idempotency key is generally not sent to the platform or used for recovery. Concurrent execution and a timeout/crash after external success can double-post. Attempts are persisted after the remote call, and there is no recovery for variants stranded in `publishing`.
4. **Default OAuth redirect is incorrect.** Configuration uses `/api/v1/channels/oauth/callback`, but callbacks are at `/api/v1/channels/{platform}/callback`. The configured default has no matching route. Platform credentials also fall back to placeholder strings instead of rejecting unconfigured connections.
5. **SQLite publication fails for persisted token expiry.** Reloaded SQLite DateTime values are naive; `publishing/service.py:299` compares them with aware UTC time. Reproduced TypeError: "can't compare offset-naive and offset-aware datetimes".
6. **Threads is missing completely.** No adapter, registry entry, OAuth configuration, assistant profile, features or tests. The spec lists eight supported channels but its adapter phase only lists seven; that inconsistency needs resolving before implementation.

## OAuth, adapter and platform gaps

- **Bluesky:** The current direct authorization URL/token exchange lacks required discovery, PAR, DPoP/nonces and hosted client metadata. It refreshes/revokes OAuth credentials using legacy session endpoints. The callback also accepts passwords/app passwords, contrary to the OAuth-only requirement. Mention facets invent `did:web:<handle>` rather than resolving the actor DID. Grapheme counting is incorrect: a family emoji counts as 7, a flag as 2 and an emoji plus skin tone as 2, although each is one grapheme cluster. [Official AT Protocol OAuth specification](https://atproto.com/specs/oauth).
- **LinkedIn:** `LINKEDIN_API_VERSION = "202401"` is retired; the official versioning documentation explicitly identifies it as a deprecated-header example. The adapter needs a supported version and revalidated requests. There is no checked-in product/permission approval matrix or dev-mode verification report. Poll support is advertised but the publish implementation does not serialize a poll. [Official versioning documentation](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-06).
- **X:** Validation uses `len(text)` rather than weighted Unicode and URL counting. Poll/quote payloads are not serialized; publication sends one post or reply, with no generated-thread sequencing or partial-thread recovery. [Official character-counting documentation](https://docs.x.com/fundamentals/counting-characters).
- **Mastodon:** Instance settings are fetched, but validation reads `instance_config` from client-supplied variant JSON instead of trusted connected-account settings. Capabilities and assistant limits remain global defaults. Instance hosts need protection against private/internal network requests. Poll/thread capabilities exceed the current publishing implementation.
- **Facebook:** Pages and encrypted Page tokens exist. Publishing only sends feed message/link fields; advertised image/video support is not implemented. Target ownership and per-target quota semantics need validation: one connected record currently holds multiple Pages.
- **Instagram:** Container creation/publish exists, but Reels are published immediately without checking processing readiness. Container IDs are not saved for retries. Carousel items are always submitted as images, so mixed/video carousels are incomplete. A supplied `children` list triggers the carousel branch but is not consumed. Media constraints, processing failures and publishing limits need stronger handling. [Meta's container-status example](https://www.postman.com/meta/instagram/request/munmruq/get-ig-container-status).
- **Reddit:** Official OAuth, permanent refresh tokens and a User-Agent exist. `list_targets()` only retrieves the first 100 subscribed subreddits, not posting eligibility. Cache refresh does not fetch the full title/post requirements; failed upstream requests can overwrite good cache data with empty rules/defaults and a new fetched timestamp. Missing/stale rules do not prevent scheduling. The multi-community endpoint can reuse identical base text for every subreddit, contrary to the spec. Its immediate-publication branch reverses the job arguments at `publishing/router.py:396`, causing failure.

### Access and operating costs

X now uses pay-per-use credits. Official listed write prices are $0.015 per ordinary post and $0.200 per post containing a URL. The Pro allowance of 250 posts could therefore incur $3.75 or $50 in X posting costs alone, before analytics and AI. The application currently has no corresponding provider-cost accounting or spend limits. These are cost calculations, not proposed customer prices. [Official X pricing](https://docs.x.com/x-api/getting-started/pricing).

Reddit states that commercial use requires permission and a contract. Approval cannot be established from this repository. Eligible free access is limited to 100 QPM per OAuth client ID, averaged over a window; the current limiter is per connected account and only wraps publication, excluding target, rules and metrics requests. It does not consume Reddit's rate-limit headers. [Commercial access requirements](https://support.reddithelp.com/hc/en-us/articles/14945211791892-Developer-Platform-Accessing-Reddit-Data), [rate-limit guidance](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki).

The remaining per-platform approval, permission, rate-limit and posting-policy verification reports required by the spec are absent. Mocked tests do not establish developer-account approval or live interoperability.

## Other incomplete requirements

- **Shared outbound rate limiting:** the singleton is constructed without a Redis client. Checking and recording are separate operations, not an atomic reservation. Only publication passes through it; refresh, metrics, targets and subreddit requests bypass it. Multi-request thread/container operations also need request-level accounting.
- **Scheduled token refresh/disconnection:** `refresh_expiring_accounts()` exists but the runner never calls it. Refresh primarily occurs just before publication or manually. Revocation failures are swallowed and the connected account is deleted instead of being retained as `needs_reauth`, as required.
- **Content/media:** drafts and variants can be created, but there are no variant add/edit/delete endpoints. The media link table exists without API attachment or publishing use. There is no storage-asset-to-platform-upload path for X media IDs, LinkedIn URNs, Bluesky blobs or Mastodon media IDs. Dimensions and alt text have columns but are not populated/editable through the upload flow. Templates and platform media processing are absent.
- **Assistant correctness:** 40 feature definitions exist, covering the requested feature names, but validation substitutes sample text/media, uses a fake Reddit target, and ignores much of the actual structured output. Shared repurposing/adaptation skips per-destination adapter validation. Errors are returned alongside successful output rather than preventing unpostable results. Platform-feature compatibility is not enforced. Platform-specific branches remain in the shared service; cached subreddit context is not consistently incorporated into prompts. There is no streaming endpoint. Failed provider/schema runs are not logged, and a missing LLM key silently produces mock content even in production.
- **Billing:** plans are an in-code dictionary, not a `plans` model/table. Usage is counted as assistant runs rather than tokens, and the existing usage ledger is not written by assistant execution. Immediate publishing bypasses scheduled-post quota checks. Check-then-count operations can race. Scheduled-post counting uses variant creation time instead of publication/reservation time. Billing reconciliation mutates subscriptions but never commits in the scheduler's session context, so updates can be rolled back. Entitlement expiry is not considered when reading grants. Missing billing credentials return a fake successful checkout instead of a configuration error in production.
- **Security/configuration:** URL repurposing follows arbitrary URLs/redirects without private-address checks or download-size bounds. Mastodon instance requests have a similar host-validation gap. Production accepts the built-in development APP_SECRET without startup validation. Encryption needs a documented durable-key/rotation approach. Email verification, password reset and workspace invitations create tokens but have no actual email delivery.
- **Analytics:** scheduled fetching selects at most 100 variants and 50 accounts without pagination/rotation, leaving others unprocessed. It filters by creation time, not publish time. Some adapters return zero metrics on API errors, causing false zero snapshots. Period reporting needs clear lifetime-versus-period semantics and a stored publication timestamp.
- **Platform-neutral core:** Reddit-specific model/adapter logic is embedded in publishing, assistant and jobs. Rate policies are central hardcoded platform data. Adding another adapter/profile currently requires core edits.
- **Tests:** missing real-adapter/common-service contract tests, workspace-isolation negatives, concurrent/crash publishing tests, PostgreSQL job behavior, real OAuth protocol checks, full media/container flows, and billing/assistant failure accounting. No CI workflow is present in the tracked repository.

## Verification and next step

Executed from `backend`:

```sh
.venv/bin/ruff check --no-cache app tests migrations
.venv/bin/python -B -m pytest -p no:cacheprovider
```

Results: lint clean; 141 tests passed in 6.39 seconds; one FastAPI/Starlette TestClient deprecation warning. Separately, a fresh temporary SQLite database successfully ran Alembic upgrade and schema-drift check; `/health` and `/ready` returned 200. These checks did not touch the existing local or production databases. PostgreSQL/Docker/live platform behavior was not verified.

Additional isolated checks reproduced the six validation TypeErrors, foreign-workspace account acceptance, foreign-workspace voice use, missing default OAuth callback route, unwired Redis limiter, incorrect grapheme counts and SQLite expiry comparison failure.

No source files were added or edited. This report is saved outside the repository. Stop here for Phase 0 review. Recommended next scope: approve a focused repair of validation contracts and workspace isolation before undertaking more adapters/features. Confirm production-data preservation and the intended Threads phase before any database reset or phase progression.
