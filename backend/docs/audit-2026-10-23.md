# Draftva backend — Phase 0 audit

Audited 23 October 2026 against the backend rewrite instructions in the root `agents.md`.

## Scope and decision

The requested backend structure already exists. This is a cleanup and boundary-refactoring exercise rather than an empty-repository rewrite. All eight channel adapters are registered, including Threads. There are no `extension`, `prospects`, standalone `profiles`, or `operations` modules to remove.

This audit makes no application, frontend, migration, infrastructure, or database changes. Its only new repository file is this report. The working tree already contains extensive earlier changes, including production Nginx/deployment work; those have not been reverted or deployed by this audit.

The user confirmed on 23 October: **“No, start fresh.”** No production data needs preserving for the proposed reset. This records the preservation answer; it does not execute a reset or approve Phase 1.

No production database/server was accessed. AWS versus Google Cloud remains undecided, and no server address or SSH host was supplied. Nothing has been launched at `api.draftva.com` by this audit.

## Confirmed stack

| Area | Actual implementation |
| --- | --- |

| OAuth encryption | Fernet/MultiFernet in `channels/oauth.py`, dedicated key with previous-key rotation support and legacy APP_SECRET-derived fallback |

| Storage | boto3/S3-compatible R2, signed uploads, validation/quarantine/scanning and quota accounting |
| Assistant | Feature/profile registries; 41 named feature declarations; structured schema validation and adapter validation |
| LLM transport | A LanguageModel protocol with an OpenAI-compatible JSON-schema HTTP implementation; other provider wire formats require another implementation |

Root instructions are stored as lowercase `agents.md`. No root/backend `CLAUDE.md` exists. `fronted/CLAUDE.md` delegates to the frontend `AGENTS.md`; no frontend changes were made during this audit.

### Confirmed platform-boundary leaks

- `app/modules/publishing/router.py`: `/reddit/multi-community-post` and Reddit payload schemas/query logic live in the generic publisher. Move them to a Reddit-owned route/service, retaining distinct user-approved variants.
- `app/modules/publishing/rate_limiter.py`: `DEFAULT_PLATFORM_POLICIES` hardcodes all eight platforms in core publishing code. The limiter mechanism can stay shared; the policies should come from adapters/configured capabilities.
- `app/modules/channels/models.py`: `ConnectedAccount.avatar_url` interprets Threads/Instagram/Meta response shapes. Normalize the avatar in adapters instead.
- `app/modules/assistant/brand.py`: a literal list of eight channel names must change whenever a platform is added. Derive it from the registry.
- `app/modules/channels/router.py` and `app/main.py`: dedicated Bluesky metadata/Reddit route registration remains explicit. Provider-owned route registration can be isolated from the core application.
- Legitimate LinkedIn feature/profile definitions belong in assistant profiles and are not old automation to delete.

Keep Starter, Pro and Business product IDs; the development `.env.example` currently omits `DODO_PRODUCT_BUSINESS` even though configuration supports it and the production template includes it.

- SMTP is a supported alternative to Resend, not automatically dead configuration.
- `draftva_TEST_DATABASE_URL` in test configuration is oddly mixed case; propose `DRAFTVA_TEST_DATABASE_URL` with a documented transition. It is test-only, not a production setting.
- Existing declared runtime libraries have current uses: FastAPI/Uvicorn/Pydantic, SQLAlchemy/Alembic/psycopg, Argon2/cryptography, httpx, google-auth/requests, Redis, multipart, boto3, regex, Pillow and MCP. No runtime dependency deletion is justified solely by retiring LinkedIn automation.
- Keep MCP only with the proposed agents extension; if explicitly removing MCP, remove its library and routes/models together.
- `requirements.txt` pins most dependencies, whereas `pyproject.toml` permits broad ranges; cryptography remains ranged in both. Use one reproducible resolution policy for release artifacts rather than silently changing packages during this audit.
